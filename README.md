# TTS Clips

Локальный редактор коротких текстов. Создайте клип, введите название и вставьте текст. Сегменты появляются после автосохранения. Нажмите на сегмент, чтобы выделить его в тексте. После закрытия браузера клипы остаются в SQLite.

## Запуск на Windows

Нужны Python 3.11 и Node.js 22. Выполните команды в PowerShell из корня проекта.

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
npm ci
npm run build
.\.venv\Scripts\python.exe -m uvicorn clips.main:create_app --factory --host 127.0.0.1 --port 8765
```

Откройте [http://127.0.0.1:8765](http://127.0.0.1:8765). При последующих запусках достаточно команды Uvicorn. После правки интерфейса повторите сборку. Для остановки сервера нажмите Ctrl+C.

Путь к базе по умолчанию — `data/clips.sqlite3`. Для изолированной рабочей области задайте `TTS_CLIPS_DB` перед запуском. Перед закрытием дождитесь статуса «Сохранено». При конфликте вкладок можно сравнить редакции и открыть сохранённую версию либо явно сохранить свой черновик поверх неё.

## VoxCPM2 на GPU-ПК

Задайте параметры в том же PowerShell перед запуском Uvicorn. Пример для существующего окружения на Windows-хосте `gpu-tts`.

```powershell
$env:TTS_CLIPS_VOX_SSH = 'gpu-tts'
$env:TTS_CLIPS_VOX_PYTHON = 'D:\projects\voxcpm2-runtime\venv\Scripts\python.exe'
$env:TTS_CLIPS_VOX_MODEL = 'D:\projects\voxcpm2-runtime\model'
.\.venv\Scripts\python.exe -m uvicorn clips.main:create_app --factory --host 127.0.0.1 --port 8765 --no-access-log
```

Сервер и SQLite работают на основном ПК. Сервер запускает Python на GPU-ПК с помощью OpenSSH в режиме BatchMode и передаёт код воркера из текущего checkout по stdin. По тому же каналу передаются задания, WAV-референсы и результаты. На GPU-ПК нужны настроенный SSH и готовое окружение VoxCPM2. Для запуска на одном ПК пропустите `TTS_CLIPS_VOX_SSH` и укажите локальные пути. Для редактора достаточно базового запуска без параметров VoxCPM2.

Воркер использует VoxCPM2 и снимок модели из рецепта TTS Books, описанного в C0A. Установленный пакет VoxCPM и запись `tts-books-model.json` сверяются при загрузке. Один процесс приложения обслуживает очередь последовательно и держит модель загруженной между заданиями. После ошибки воркера, тайм-аута или отмены активной работы следующее задание запускает новый процесс. Обновление кода воркера требует перезапуска приложения.

Откройте «Студию голоса». Для Voice Design введите описание и фразу. Для Voice Clone загрузите PCM WAV до 30 секунд и 16 МиБ и введите фразу. Для преобразования WAV в mono PCM16 48 кГц нужен FFmpeg на основном ПК. Прослушайте пробу и нажмите «Закрепить и выбрать». Для Design референсом станет WAV пробы. Для Clone используется загруженный образец, приведённый к рабочему формату.

Голос клипа сохраняется в его редакции. WAV хранятся рядом с базой, по умолчанию в `data/clips.audio`. Для переноса данных сохраните базу и каталог аудио вместе при остановленном сервере. Запускайте один экземпляр приложения на каждую базу.

## Дубли и выборочная озвучка

Нажмите «Озвучить недостающие», чтобы обработать сегменты без пригодного выбранного дубля для текущего голоса. Сегменты, уже стоящие в очереди, пропускаются. Чтобы озвучить конкретные реплики, поставьте флажки рядом с ними и нажмите «Озвучить выбранные». Без флажков команда работает с открытым сегментом.

Откройте сегмент, чтобы увидеть его дубли. «Повторить параметры» сохраняет seed, «Новый вариант» выбирает другой. У каждой попытки собственный номер, даже когда WAV совпадает побайтно. A/B проигрывает два назначенных дубля с начала через общий плеер. «Выбрать» меняет активный дубль, а «Вернуть предыдущий» возвращает прошлый выбор. В разделе «Прослушивание и решение» можно отметить прослушивание, принять или отклонить вариант и записать заметку.

Первый готовый дубль выбирается автоматически для актуального сегмента, если выбора ещё нет. Если выбранный дубль отклонён, «Озвучить недостающие» добавит кандидат. Выбор заменяется вручную. Изменённые реплики и голоса сохраняют прежнее аудио в истории. Новые дубли появляются по мере готовности, и текст можно редактировать во время синтеза.

При остановке, ошибке или перезапуске готовые WAV и выборы остаются в базе. После перезапуска команда «Озвучить недостающие» продолжит заполнение пропусков. Для незавершённых дополнительных дублей снова выберите нужные сегменты или параметры исходного дубля. При сбое отправки кнопка повтора использует тот же ключ команды. В API повтор POST на `/api/clips/{id}/generations` с тем же `key` и телом возвращает прежний пакет. Для новой попытки нужен новый ключ.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
npm run build
```

Тесты проверяют сегментацию, конфликт редакций, оба голосовых сценария, тёплый воркер, ошибки протокола и тайм-аут. Проверки дублей охватывают повтор команды, выбор и возврат, правку текста во время синтеза, отмену, сбой и перезапуск. Архитектура следующих этапов описана в [C0A](docs/C0A_Source_Audit_and_Architecture_Proposal.md).
