# TTS Clips

Локальное приложение для озвучки готового русского перевода. Создайте клип, затем работайте в трёх вкладках:

1. **Подготовка.** Вставьте текст, разберите замечания и выберите голос или создайте пробу.
2. **Озвучка.** Озвучьте недостающие сегменты. Поочерёдно слушайте варианты через один плеер. «Выбрать» назначает дубль для сборки. Для замечаний проверьте реплику на слух и примите дубль, если речь подходит.
3. **Экспорт.** Выберите формат и паузы, проверьте сборку, затем соберите, прослушайте и скачайте файл. Кнопка у препятствия открывает нужный сегмент.

Можно возвращаться к любой вкладке. Клип, дубли, решения и история экспортов сохраняются.

## Запуск на Windows

Нужны Python 3.11 и Node.js 22. Выполните команды в PowerShell из корня проекта.

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
npm ci
npm run build
.\.venv\Scripts\python.exe -m uvicorn clips.main:create_app --factory --host 127.0.0.1 --port 8765
```

Откройте [http://127.0.0.1:8765](http://127.0.0.1:8765). При последующих запусках достаточно команды Uvicorn. После правки интерфейса повторите сборку. Для остановки сервера нажмите Ctrl+C.

Путь к базе по умолчанию — `data/clips.sqlite3`. Для изолированной рабочей области задайте `TTS_CLIPS_DB` перед запуском. Перед закрытием дождитесь статуса «Сохранено». При конфликте вкладок можно сравнить редакции и открыть сохранённую версию либо явно сохранить свой черновик поверх неё.

## Подготовка текста

Вставляйте готовый к произнесению русский текст. До импорта раскройте числа, даты, время, величины, единицы и неоднозначные сокращения словами в нужных падежах. После автосохранения блок «Готовность текста» показывает найденные письменные формы. Нажмите на замечание, чтобы выделить фрагмент в редакторе. Проверка оставляет исходник и возможность сохранить черновик.

При озвучке, повторе или восстановлении с оставшимися замечаниями нажмите «Озвучить с предупреждениями», чтобы подтвердить выбранную команду. Клиент API получает от сервера `422` с `detail.code = "speech_ready"` и повторяет команду с `speech_confirmation`, полученным для этой редакции и набора замечаний.

## VoxCPM2 на GPU-ПК

Задайте параметры в том же PowerShell перед запуском Uvicorn. Пример для существующего окружения на Windows-хосте `gpu-tts`.

```powershell
$env:TTS_CLIPS_VOX_SSH = 'gpu-tts'
$env:TTS_CLIPS_VOX_PYTHON = 'D:\projects\voxcpm2-runtime\venv\Scripts\python.exe'
$env:TTS_CLIPS_VOX_MODEL = 'D:\projects\voxcpm2-runtime\model'
.\.venv\Scripts\python.exe -m uvicorn clips.main:create_app --factory --host 127.0.0.1 --port 8765 --no-access-log
```

Сервер и SQLite работают на основном ПК. Сервер запускает Python на GPU-ПК с помощью OpenSSH в режиме BatchMode и передаёт код воркера из текущего checkout по stdin. По тому же каналу передаются задания, WAV-референсы и результаты. На GPU-ПК нужны настроенный SSH и готовое окружение VoxCPM2. Для запуска на одном ПК пропустите `TTS_CLIPS_VOX_SSH` и укажите локальные пути. Для редактора достаточно базового запуска без параметров VoxCPM2.

Воркер использует VoxCPM2 и снимок модели из рецепта TTS Books, описанного в C0A. Установленный пакет VoxCPM и запись `tts-books-model.json` сверяются при загрузке. Один процесс приложения обслуживает очередь последовательно и держит модель загруженной между заданиями. После ошибки воркера, тайм-аута или отмены активной работы следующее задание запускает новый процесс. Обновление кода воркера требует перезапуска приложения.

В «Подготовке» нажмите «Создать голос». «По описанию» предлагает три пресета Voice Design. При необходимости измените английское описание в дополнительных настройках. «По образцу» принимает PCM WAV до 30 секунд и 16 МиБ (Voice Clone). Для преобразования в mono PCM16 48 кГц нужен FFmpeg. Создайте пробу, прослушайте и нажмите «Использовать». Для Design референсом станет WAV пробы, для Clone — загруженный образец.

Голос клипа сохраняется в его редакции. WAV хранятся рядом с базой, по умолчанию в `data/clips.audio`. Для переноса данных сохраните базу и каталог аудио вместе при остановленном сервере. Запускайте один экземпляр приложения на каждую базу.

## Дубли и выборочная озвучка

Нажмите «Озвучить недостающие», чтобы обработать сегменты без пригодного выбранного дубля для текущего голоса. Сегменты, уже стоящие в очереди, пропускаются. Чтобы озвучить конкретные реплики, нажмите «Отметить», поставьте флажки и нажмите «Озвучить отмеченные». Команда «Озвучить сегмент» работает с открытой репликой.

Откройте сегмент, чтобы увидеть его дубли. «Повторить параметры» сохраняет seed, «Новый вариант» выбирает другой. У каждой попытки собственный номер, даже когда WAV совпадает побайтно. Кнопка «Слушать» запускает соответствующий дубль в общем плеере. «Выбрать» меняет активный дубль, а «Вернуть предыдущий» возвращает прошлый выбор. В разделе «Прослушивание и решение» можно отметить прослушивание, принять или отклонить вариант и записать заметку.

Первый готовый дубль выбирается автоматически для актуального сегмента, если выбора ещё нет. Если выбранный дубль отклонён, «Озвучить недостающие» добавит кандидат. Выбор заменяется вручную. Изменённые реплики и голоса сохраняют прежнее аудио в истории. Новые дубли появляются по мере готовности, и текст можно редактировать во время синтеза.

При остановке, ошибке или перезапуске готовые WAV и выборы остаются в базе. После перезапуска команда «Озвучить недостающие» продолжит заполнение пропусков. Для незавершённых дополнительных дублей снова выберите нужные сегменты или параметры исходного дубля. При сбое отправки кнопка повтора использует тот же ключ команды. В API повтор POST на `/api/clips/{id}/generations` с тем же `key` и телом возвращает прежний пакет. Для новой попытки нужен новый ключ.

## Whisper QC

Whisper запускается на CPU основного ПК в отдельном Python-окружении. Для распознавания используется локальная многоязычная модель CTranslate2. Синтез продолжает работать в настроенном окружении VoxCPM2.

```powershell
py -3.11 -m venv output/whisper-runtime
.\output\whisper-runtime\Scripts\python.exe -m pip install -r requirements-whisper.txt
.\output\whisper-runtime\Scripts\hf.exe download Systran/faster-whisper-small config.json model.bin tokenizer.json vocabulary.txt --revision 536b0662742c02347bc0e980a01041f333bce120 --local-dir output/whisper-small
$env:TTS_CLIPS_WHISPER_PYTHON = (Resolve-Path output/whisper-runtime/Scripts/python.exe).Path
$env:TTS_CLIPS_WHISPER_MODEL = (Resolve-Path output/whisper-small).Path
```

Задайте эти переменные вместе с настройками VoxCPM2 и запустите Uvicorn. Загрузка модели нужна только при настройке. Запуск проверок использует локальные файлы. При отсутствии модели озвученный WAV остаётся доступен, а карточка показывает статус настройки.

После публикации каждого нового дубля запускается проверка речи. Раскройте «Дополнительные действия и проверка», затем «Подробности проверки» на карточке дубля, чтобы увидеть ожидаемую фразу, полную расшифровку, расшифровку последних 12 секунд и причины замечаний. Для WAV длительностью до 12 секунд хвост совпадает со всем файлом. Фильтр «Только с замечаниями» сокращает список до сегментов, требующих внимания для текущего голоса.

«Проверьте точность произнесения» появляется отдельно от оценки полноты, в том числе при `verified`. Правила ищут возможные подмены числительных и слов в сопоставленных фрагментах. Если распознавание разошлось с ожидаемым текстом, послушайте WAV и решите, можно ли принять дубль. Результат, версия правил и основание доступны в `pronunciation_integrity`. Новая версия этих правил проверяет сохранённые расшифровки отдельно, сохраняя прежние QC и WAV.

Кнопка «Проверить WAV» доступна и для дублей, созданных до C1.4. «Проверить повторно» использует готовый WAV. Совпадение WAV, текста, языка, отпечатка распознавателя и версии правил возвращает сохранённый отчёт. Другой отпечаток создаёт отчёт новой версии. Отчёты доступны через `GET /api/clips/{id}/takes/{take_id}/qc`. После прерывания очереди незавершённые проверки возобновляются при запуске. Выбор дубля и решение слушателя сохраняются независимо от проверки.

Правила оценки полноты речи и окончания адаптированы из [TTS Books](https://github.com/deelexx86/tts-books/blob/b55371085c1c515bc97855d6005d65d613f1f7bd/src/tts_books/speech_completion.py). Для локального распознавания используется [faster-whisper](https://github.com/SYSTRAN/faster-whisper/tree/v1.2.1).

## Сборка и экспорт

В панели «Сборка и экспорт» задайте режим, формат и паузы. По умолчанию тишины перед началом нет, между сегментами вставляется 150 мс. Нажмите «Проверить сборку», чтобы увидеть состав, длительность и препятствия. Кнопка рядом с замечанием открывает соответствующий сегмент во вкладке «Озвучка».

Режим «Окончательная» допускает выбранные дубли с актуальным `verified` по полноте и `clear` по точности произнесения либо с отметкой о прослушивании и ручным принятием. Для автоматического допуска требуется настроенный Whisper с тем же отпечатком модели, что и в отчёте. Черновая сборка допускает замечания QC и непроверенные дубли с предупреждениями. Отсутствующий, повреждённый, отклонённый или устаревший дубль блокирует оба режима.

После нажатия «Собрать аудио» результат появится в истории с плеером и ссылками для скачивания. WAV-мастер содержит mono PCM16 48 кГц. Для MP3 нужен FFmpeg с `libmp3lame` в PATH. Сервер кодирует тот же мастер с битрейтом 128 кбит/с, а при ошибке кодера сохраняет WAV. Изменение пауз и формата использует существующие дубли и отчёты QC.

В истории хранятся снимки редакции, порядка дублей, оснований допуска, пауз и хешей файлов. Экспорты сохраняются в `data/clips.exports` рядом с базой. При переносе данных скопируйте базу, исходные WAV и каталог экспортов при остановленном сервере.

## Восстановление речи

Если Whisper пометил дубль как `likely_defect`, на его карточке появляется «Восстановить дубль». Команда «Восстановить проблемные сегменты» обрабатывает выбранные дубли текущего текста и голоса. Чтобы включить `suspect`, отметьте «Включить сомнительные». Для запуска нужны сохранённый клип и оба рабочих окружения.

Сначала Clips повторяет полную реплику с другим seed. Если результат не прошёл проверку, Clips ищет ближайшую к середине границу предложений в диапазоне 30–70% длины текста. При наличии границы синтезирует две части с тем же альтернативным seed, вставляет паузу 500 мс и проверяет весь составной WAV в Whisper. При отсутствии границы пакет сообщает об этом и завершает обработку данного сегмента.

Для обеих попыток требуется `verified` и проверяется сохранение полноты текста. У составного дубля длительность должна составлять 80–130% от исходной, а сигнал на конце первой части должен оставаться не выше −32 дБFS. Если проверка не пройдена, карточка показывает причины. Такой дубль можно прослушать и допустить к окончательному экспорту вручную. Правила адаптированы из [TTS Books](https://github.com/deelexx86/tts-books/blob/b55371085c1c515bc97855d6005d65d613f1f7bd/src/tts_books/speech_recovery.py).

Готовые попытки появляются среди дублей исходного сегмента. Прослушайте варианты по очереди и явно выберите нужный. Исходная запись, пользовательский выбор и замечания сохраняются. В отчёте операции доступны ID исходного дубля, стратегия, seed, хеши WAV и частей, а также ID отчёта QC и причины замечаний. При отмене готовые WAV и завершённые части остаются доступны.

Повтор `POST /api/clips/{id}/recoveries` с теми же `key` и телом возвращает тот же пакет. Одновременно для одного исходного дубля выполняется одна операция восстановления. После перезапуска ожидающие задания и проверки QC продолжаются. Синтез, прерванный посередине, получает статус «Прервано», а сохранённые части остаются в истории. Одна операция делает максимум один полный повтор и одну составную попытку.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
npm run test:web
npm run build
```

Тесты проверяют сегментацию, голоса, дубли, QC, подготовку текста и ручной допуск при лексических замечаниях. Для восстановления проверяются предел попыток, допустимость границы, точность составного PCM, решение о допуске, отмена и перезапуск. Тесты экспорта сверяют порядок кадров, блокировки и сохранение истории. Интеграционная проверка MP3 запускается при наличии FFmpeg. Для автоматических тестов модели не требуются. Архитектура описана в [C0A](docs/C0A_Source_Audit_and_Architecture_Proposal.md). Замеры и правила лексической проверки приведены в [отчёте C1.8](docs/C1.8_Speech_Ready_and_Integrity_Validation.md).
