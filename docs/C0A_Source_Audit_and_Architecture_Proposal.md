# TTS Clips · C0A. Аудит исходников и архитектура приложения

**Решение.** Для короткого текста единица работы — клип. Пользователь редактирует текст, выбирает голос, слышит результат и заменяет только неудачные фрагменты. Предлагается локальное веб-приложение с одним Python-сервером, SQLite для состояния и WAV-файлами для звука. Из Books стоит выделить вызов VoxCPM2, проверку полноты речи и операции с PCM. План клипа, очередь работ, выбор дублей, Voice Design и экспорт получают собственные контракты Clips.

**Основание.** Исследована отдельная копия `deelexx86/tts-books` на `b55371085c1c515bc97855d6005d65d613f1f7bd`, коммит *Persist production chapter plans, speech takes and review decisions*. Ссылки в аудите закреплены за этим деревом. После аудита описаны проектные решения и критерии их будущей проверки. [Снимок репозитория][tree]

## 1. Как работает production в Books

Проверенный вход — `tts_books.production_cli`. Команда `plan` строит план по главе и закреплённому голосу. `generate` получает явные ID сегментов и публикует кандидатов. `qc` проверяет конкретный дубль, `review` хранит решение слушателя, `assemble` собирает выбранное. Есть второй путь: `speech_cli` создаёт R4A-прогон и аудит, а `register_legacy` проверяет совпадение плана, источника, референса и аудио перед регистрацией старых WAV в B1. Скрипт `render-narrator-chapter.ps1` использует именно `speech_cli`. Для нового приложения исходной точкой служат операции над дублями в B1. **Три детали, влияющие на реализацию.**

1. Воркер формирует `(описание)текст` при непустом описании. В Design он передаёт модели `reference_wav_path=None`, в Clone — путь к WAV. Production-адаптер жёстко выбирает Clone и ожидает `effective_text == intent.text`. Установка режима в UI поверх прежнего адаптера сломала бы проверку. В Clips у запроса отдельно хранятся произносимый текст и фактическая строка модели. Whisper сверяется с первым. [Генерация и результат][worker] · [проверка ответа][voxadapter]
2. Модель переиспользуется, пока жив процесс. B1 вызывает `synthesize` отдельно для обычного сегмента, а этот метод каждый раз запускает subprocess и проверяет шесть файлов модели. У Lab длительную жизнь процесса обеспечивает Qt. Для быстрых дублей Clips нужен собственный клиент JSON Lines: события `hello/status/done/error`, один активный запрос, привязка по ID и остановка процесса при отмене. [Вызов для сегмента][generate] · [запуск процесса][voxadapter] · [Qt-клиент][qt]
3. Вердикт `verified` относится к полноте речи. Например, пропуск двух последних слов в обоих распознаваниях даёт `likely_defect`. Покрытие ниже 0,82 при отсутствии более сильного признака даёт `suspect`. Нормализация включает «ё/е», удаление знака ударения и несколько форм слова «тысяча». Исходная идентичность Whisper учитывает адаптер и файл весов. Для повторного использования оценки Clips должен учитывать также processor, настройки распознавания и версию правил. Решение о тембре, интонации и ударениях остаётся за слушателем. [Эвристика][qc] · [идентичность ASR][asr] · [кеш результата][assess]

## 2. Минимальная архитектура Clips

**Один сервер на loopback.** Браузер получает готовую статику и HTTP API с одного адреса. Для клиента выбираем TypeScript, React и Vite на этапе сборки. Для сервера — Python 3.11, FastAPI и Uvicorn в одном процессе. Python позволяет выделить проверенные операции со звуком без второго прикладного стека. SQLite из stdlib хранит текст и решения, локальный каталог хранит аудио по SHA-256. Node нужен при сборке интерфейса. Для фоновых работ достаточно таблицы заданий и одного исполнителя в серверном процессе.

```text
Браузер (редактор, прослушивание, выбор дублей)
  │ HTTP: команды / снимки / поток аудио
  ▼
Clips API ── операции над клипом ── SQLite + каталог неизменяемых файлов
                  │                          ▲
                  └─ очередь SQLite → исполнитель ── публикация результата
                                         ├─ VoxCPM2 · JSONL · тёплый процесс
                                         ├─ Whisper · JSON · процесс на пакет WAV
                                         └─ FFmpeg · входной референс / MP3
```

**Границы кода.** В модуле `clips.core` живут сегментация, хеши входов, оценка Whisper и правила пригодности. Сценарии `clips.application` сохраняют редакцию, создают работу, публикуют дубль, меняют выбор и экспортируют снимок. Адаптеры владеют SQLite, файлами, subprocess и протоколом конкретной модели. В первой версии Clips стандартный рецепт использует seed 42, CFG 2,0 и 10 шагов. Для обеих вкладок принимаем диапазон seed от 0 до 2³¹ − 1, общий для Lab и production CLI. В Design обязательны описание без круглых скобок и пробная фраза. В Clone управляющее описание по умолчанию пустое. Воркеры получают конкретный вход и приватный путь вывода, сервер проверяет результат и публикует его. Клиент оперирует ID и URL аудио. Пакет Clips собирается и запускается без установленного Books или доступа к его checkout.

**Граница runtime.** У API нет импортов ML. Исполнителю задаются интерпретатор и локальная модель для Vox и Whisper, допускается один совместимый интерпретатор для обоих. За исходную точку Vox принимаются upstream `300e4260b509066151d623dc9c0aa922cf82232b` и модель `7936080b41163874f38610f46f438e2c0757f9fd`. Это пины из проверенного исходника. Отпечаток установленного набора файлов и версии зависимостей записываются для каждой сессии воркера. Начало работы проверяет наличие нужной модели или кодека для выбранной операции. Обновление runtime перезапускает воркер. Существующий lock Books служит справкой для Vox, а авторизация, удалённые сервисы, подбор драйверов и матрица оборудования лежат за границами C0A. [Пины и состав модели][pins] · [ограничения runtime][constraints]

## 3. Текст, редакции и идентичность сегмента

**Предлагаемая политика `clips-text-v1`.** Клип хранит введённый plain text с переводами строк LF (CRLF и CR приводятся к LF на входе). Орфография, регистр, «ё», ударения, пробелы и пунктуация сохраняются. Пустой черновик сохраняется. Сервер строит план чистой функцией от текста и версии политики. Выход содержит упорядоченные непересекающиеся срезы `[start,end)` в кодовых точках Unicode. Редактор переводит их в UTF-16 для выделения в DOM. SHA-256 строк считается по UTF-8.

1. Каждая непустая строка образует отдельную область разбиения. На её краях пробельные символы, а между строками LF входят в срезы-разделители. Разделитель принадлежит исходному тексту и не создаёт работу синтеза.
2. Внутри области длиной до 240 кодовых точек оставляем один сегмент. Для более длинной берём последнюю границу предложения до лимита включительно (конечные `.!?…`, возможные закрывающие кавычки или скобки, затем пробел). Если её нет, берём последний пробельный разрыв до лимита. При сплошном длинном токене режем на лимите. Граница предложения включает завершающую пунктуацию. Пробельную последовательность на разрезе целиком записываем разделителем, внутренние пробелы остаются в произносимом тексте. Продолжаем с первого следующего непробельного символа. 240 — стартовый параметр для сравнения голосовых проб, изменение алгоритма требует новой версии.
3. Конкатенация всех срезов, включая разделители, должна точно восстановить сохранённый текст. Сегмент получает точный срез как `spoken_text`. Например, в «Да.\n\nДа.» два разных сегмента с диапазонами [0,3) и [5,8), между ними разделитель [3,5). Одинаковая фраза в двух местах может иметь разные выбранные дубли.

**Что переживает правку.** При автосохранении клиент посылает операции замены диапазона с базовой редакцией. Сервер переносит старые диапазоны через эти операции и заново строит детерминированные границы. Если старый интервал целиком сохранился, отображается в ровно один новый сегмент и текст совпал, сохраняется его `segment_id`, даже при сдвиге позиции. Новый или пересекающий правку интервал получает новый ID. При совпадении строк по разным позициям либо полной замене без надёжного отображения старая привязка не угадывается. У прежних дублей остаётся история редакции. Вставка отдельной строки перед двумя одинаковыми строками сохраняет выбор каждой исходной строки. Такая проверка требует независимых ID для экземпляра сегмента и для содержимого.

## 4. Модель данных и правила публикации

| Запись | Существенные поля и связи |
|---|---|
| `Clip`, `Revision` | У клипа есть название, текущая редакция и версия выбора. Неизменяемая редакция хранит parent, текст с LF, его хеш, язык, версию разбиения и ID закреплённого голоса (может отсутствовать в черновике). Одна редакция содержит много позиций. |
| `RevisionSpan` | Ключ (редакция, порядковый номер), вид «речь/разделитель», start/end. У речи есть ID экземпляра сегмента, хеш произносимого текста и ключ материала. Сохранившийся экземпляр может входить в несколько редакций. |
| `VoiceVersion`, `Asset` | Неизменяемая версия голоса указывает на закреплённый WAV по SHA-256 и происхождение. Для Design хранит описание, пробный текст, seed, CFG, steps, модель, фактический вход и ID пробы. Для Clone — хеш загрузки и параметры приведения в рабочий PCM. У файла хранятся тип, размер, а у WAV также формат и число кадров. Имена пользователя остаются метаданными. |
| `Take` | ID попытки, сегмент, редакция-источник, ключ материала, `spoken_text`, фактический вход, ID голоса, параметры и seed, отпечаток модели/воркера, метрики исполнения, SHA-256 WAV. Идентификатор попытки уникален даже при совпадении байтов двух результатов. |
| `QCReport` | Уникальный ключ (хеш WAV, хеш произносимого текста, язык, отпечаток Whisper с настройками, версия оценки). Полный и хвостовой транскрипты, статус и числовые признаки. Смена версии оставляет прежний отчёт в истории. |
| `Selection`, `TakeReview` | Выбор привязан к (клип, экземпляр сегмента, ключ материала), содержит текущий и предыдущий take ID. Отдельно на дубле хранятся отметка прослушивания, принято/отклонено и заметка. Смена выбранного дубля увеличивает версию выбора. |
| `Job`, `JobItem` | Вид операции, ключ идемпотентности, снимок параметров, ревизия, статус, запрос отмены. У элемента есть порядковый номер, цель, попытка, ошибка и ссылка на опубликованный результат. Уникальность результата по элементу исключает двойную публикацию при повторе запроса. |
| `Export` | Редакция, упорядоченные (сегмент, дубль, хеш WAV), основания допуска, паузы в кадрах, режим, формат, настройки и версия кодера, хеш результата. Файл можно вновь скачать после изменения текста. |

**Ключи и последствия изменений.** Ключ материала — SHA-256 версионированного массива из произносимого текста, языка, версии голоса и способа подготовки входа Clone. Настройки новой попытки (seed, CFG, steps, версия движка) записываются в рецепт дубля. Их изменение создаёт вариант, старый по-прежнему можно выбрать. Для ключей используется одно каноническое представление JSON на сервере (UTF-8, фиксированный порядок полей и представление чисел); хеш аудио считается по фактическим байтам файла.

| Событие | Последствие для пользователя |
|---|---|
| Правка слова или границы | Только затронутые экземпляры теряют применимый выбор. Неизменённые сегменты с прежним материалом доступны сразу. |
| Смена закреплённого голоса или языка | У всех сегментов меняется ключ материала. Предыдущие записи можно прослушать в истории. Возврат того же материала позволяет восстановить его выбор. |
| Ещё один дубль, повтор QC или отказ ASR | Существующая выбранная запись сохраняется. Повтор QC использует готовый WAV. Один и тот же отчёт пригоден для идентичных входов. |
| Смена паузы, формата или выбора | Меняется снимок экспорта. Исходные WAV и результаты распознавания пригодны для следующей сборки. |

**Публикация и сбои.** Работа захватывает неизменяемый вход до запуска модели. Исполнитель пишет в staging на том же томе, проверяет RIFF, PCM16 mono 48 кГц, положительное число полных кадров, наличие ненулевых сэмплов и хеш. Полностью записанный файл публикуется по хешу, затем короткая транзакция БД создаёт дубль и завершает элемент задания. Уже существующий файл сверяется. После сбоя между этими шагами возможен файл без ссылки, но в БД нет «готового» дубля без опубликованного файла. При старте незавершённые работы переходят в «Прервано», готовые элементы сохраняются, повтор запускает только оставшиеся. Удалять staging можно после установления, что у него нет активного владельца. Отсутствующий или повреждённый опубликованный файл помечается недоступным при чтении и блокирует сборку.

Элемент проходит состояния «В очереди → Выполняется → Готово», с отдельными исходами «Ошибка», «Прервано» и «Отменено». Синтез и последующий QC имеют разные результаты: валидный WAV публикуется до запуска ASR. Ошибка конкретного сегмента оставляет остальные цели в очереди. При недоступном воркере задание завершается с перечнем готовых и оставшихся целей.

Отмена останавливает текущий subprocess при необходимости и закрывает незавершённые элементы. Если транзакция публикации успела первой, результат виден как завершённый. Иначе запоздалый ответ отклоняется по ID попытки и статусу задания. Результат параллельной правки текста или голоса остаётся в истории той редакции, на которой начался синтез. Текущий выбор изменяется только после проверки сегмента и материала в действующей редакции. Долгий вызов модели и кодирование выполняются вне транзакции БД.

## 5. Работа в браузере

**Основной экран.** На широком экране слева текст и сегменты, справа настройки голоса либо дубли выбранного сегмента. Внизу один плеер с названием сегмента и дубля, временем, перемоткой и переходом к соседней реплике. На узком экране редактор занимает всю ширину, дубли и голос открываются в отдельной панели с возвратом к тому же месту. Во время прослушивания сохраняются курсор, прокрутка и активный сегмент.

| Момент | Действие и видимая обратная связь |
|---|---|
| Вставить и исправить текст | Обычный многострочный ввод с undo. Сервер возвращает карту срезов и число сегментов. Выбор строки списка выделяет соответствующую фразу в тексте. Видны «Сохраняется», «Сохранено» или конкретная ошибка. При очистке остаётся черновик. Синтез доступен после сохранения непустой редакции и выбора голоса. |
| Найти голос | В панели две вкладки. **Design** принимает описание и короткую пробную фразу. Можно прослушать пробы с разными seed и закрепить одну кнопкой «Использовать этот голос». **Clone** принимает локальный PCM WAV (до 16 МиБ и 30 с), даёт прослушать референс и тест-фразу. Сервер проверяет декодирование и длительность, при необходимости приводит референс к mono PCM16 48 кГц, сохраняет его хеш. Отказ приводит к сообщению у поля файла. В обоих случаях последующие реплики звучат через Clone с одним закреплённым образцом. Пробы хранятся отдельно от дублей текста. |
| Получить озвучку | По умолчанию «Озвучить недостающие» обрабатывает только сегменты без пригодного выбора. Рядом доступно число целей. Для первого валидного дубля при пустом выборе выполняется условный автовыбор с отметкой «Первый дубль». Он не означает принятия человеком. Кнопка «Новый дубль» всегда создаёт попытку для отмеченных сегментов. «Новый вариант» меняет seed, «Повторить параметры» сохраняет рецепт. Конкретные параметры доступны в деталях дубля. |
| Дождаться или прервать | У работы видны этап и счётчик («Синтез 2 из 4», «Проверка речи»), у строки — очередь, синтез, доступный WAV, проверка или ошибка. Готовые WAV можно слушать до окончания всей партии. «Остановить» сохраняет готовые дубли. При возвращении в клип сервер восстанавливает состояние по ID работы. Отказ Whisper оставляет действие «Повторить проверку», отказ синтеза — «Повторить этот сегмент». |
| Разобрать замечание | Фильтры «Требуют внимания» и «Без дубля». Панель показывает ожидаемый текст, полное распознавание, отдельно последние слова и причину срабатывания. Три содержательных состояния QC — «Полнота подтверждена», «Проверить на слух», «Вероятен дефект». Остальные состояния обозначают отсутствие результата или сбой. Каждое замечание ведёт к плееру этого дубля. |
| Сравнить и выбрать | Кнопки A/B проигрывают дубли одного сегмента с начала или с сохранённой позиции, с ограничением по длительности. В каждый момент играет один источник. В строке видны длительность, QC, решение слушателя и отдельная отметка «Выбран». Доступны «Выбрать», «Вернуть предыдущий», «Отклонить» и «Прослушал целиком и принимаю». Решение человека записывается явно. Прослушивание отрывка и успешный QC сами по себе не выставляют ручное принятие. |
| Скачать клип | Диалог показывает длительность WAV по кадрам, паузы, выбранные варианты и список препятствий с переходом к сегменту. «Черновик с замечаниями» разрешает непроверенную речь. Выпуск доступен, когда каждый выбранный дубль прошёл актуальный QC либо принят после прослушивания. Отказанный, устаревший, отсутствующий или повреждённый дубль блокирует оба режима. Готовый WAV или MP3 скачивается из истории экспорта. |

**Клавиатура и доступность.** Основные действия доступны через Tab и Enter, Space управляет плеером при фокусе на нём и вводит пробел в редакторе. Заголовки и названия кнопок содержат номер сегмента/дубля там, где действие повторяется. Статусы имеют текст, фокус виден, прогресс объявляется при смене этапа. При закрытии панели фокус возвращается к вызвавшей кнопке. Автосохранение с конфликтующей базой оставляет набранный текст на экране и предлагает сравнить с сохранённой версией.

### Контракты на границе браузера

| Операция API | Результат и защита от гонок |
|---|---|
| `POST /clips`, `GET /clips/{id}`, `PATCH /clips/{id}` | Создание черновика, снимок для открытия и автосохранение текста/языка/голоса. PATCH проверяет `base_revision`, отдаёт новую редакцию и срезы. Ответ 409 содержит текущую редакцию для восстановления после конфликта вкладок. |
| `POST /voices/previews`, `POST /voices` | Проба Design или Clone возвращает ID работы. Закрепление принимает ID готовой пробы либо загруженный WAV, возвращает неизменяемый ID голоса. Замена голоса создаёт редакцию клипа. |
| `POST /clips/{id}/jobs`, `GET /jobs/{id}`, `POST /jobs/{id}/cancel` | Вид работы, снимок редакции, явные segment/take ID, рецепт и ключ повтора команды. Ответ 202 с ID. Во время работы клиент опрашивает состояние примерно раз в секунду, после терминального статуса обновляет снимок и прекращает опрос. Повтор команды с тем же ключом и телом возвращает существующую работу. При другом теле сервер возвращает конфликт. |
| `PATCH /clips/{id}/selections/{segment_id}`, `PATCH /takes/{id}/review` | Выбрать, вернуть прежний выбор или записать решение. Сервер проверяет ревизию, версию выбора/решения, принадлежность дубля и материал. Автовыбор первого дубля допускается только в текущей редакции при прежней версии пустого выбора. |
| `POST /clips/{id}/exports`, `GET /exports/{id}`, `GET /assets/{id}/audio` | Запрос фиксирует снимок и либо перечисляет блокирующие сегменты, либо возвращает задание на сборку. Готовый экспорт имеет ссылку для скачивания. Аудио отдаётся по ID с поддержкой Range для перемотки. Локальные пути модели и файлов остаются на сервере. |

**Сборка.** Стартовые настройки клипа — 0 мс до начала и 150 мс между сегментами. Паузы задаются отдельно от исходного текста. Для N ≥ 1 число кадров мастера равно сумме кадров выбранных дублей плюс начальная пауза и (N − 1) межсегментных пауз, где 1 мс = 48 кадров. WAV собирается из проверенного mono PCM16 48 кГц. Для MP3 сервер кодирует этот же мастер внешним FFmpeg с `libmp3lame`, один профиль 128 кбит/с mono. Записываются параметры и хеш мастера, проверяются завершение кодера и декодируемость результата. Ошибка кодера не лишает пользователя WAV. Оба формата привязаны к зафиксированному набору дублей. Если выбор изменился в процессе, интерфейс подписывает результат как экспорт прежнего снимка. Сравнение длительности MP3 при приёмке учитывает задержку и заполнение кодера.

## 6. Следующая стадия C1 · порядок реализации и приёмка

| Шаг и зависимость | Законченная поставка | Проверка перед переходом дальше |
|---|---|---|
| **C1.1. Редактор и план**. Старт проекта | Локальный сервер, оболочка UI, SQLite, создание и открытие клипа, автосохранение и отображение серверных срезов. | После перезапуска восстанавливается точный текст. Зафиксированные примеры для CRLF, пустых строк, «ё», ударений, emoji, кавычек, повтора фраз и длинного слова дают одинаковые границы и полное покрытие. Вставка до дубликатов сохраняет ID по позиции, вторая вкладка получает управляемый конфликт. |
| **C1.2. Голос и первый звук**. После C1.1 | Хранилище WAV, исполнитель заданий, Vox-воркер. Два входа в один рабочий поток: Design → проба → закрепление или Clone → загрузка → проба. Озвучка одного сегмента и плеер. | Тестовый воркер проверяет связь запроса и ответа, текст с управляющим описанием, хеш референса, порядок событий, тайм-аут и отмену. На настроенном runtime человек прослушивает Design и Clone, затем две реплики одним закреплённым голосом. На второй заявке при живом процессе наблюдается повторное использование модели. |
| **C1.3. Дубли и выборочная генерация**. После C1.2 | Пакет явных целей, пропуск пригодных, новые варианты, A/B, выбор, возврат, заметка, принятие и отклонение. Редактор работает во время синтеза. | Три сегмента, новый дубль только для второго: первый и третий сохраняют ID и SHA-256 WAV, у второго сохранён прежний выбор до явной замены. Повтор HTTP-команды не удваивает результат. Прерывание после одного результата, перезапуск и правка текста во время синтеза дают согласованные историю и текущий выбор. |
| **C1.4. Whisper QC**. Требуются дубли C1.3 | Постановка QC после синтеза, проверка по запросу, кеш, расшифровка и фильтр замечаний. Поддерживается ручной допуск после прослушивания. | Офлайн-фикстуры для точного текста, пропущенного конца, ложного срабатывания и ошибки ASR. Повтор по прежнему ключу использует отчёт, изменение версии оценки даёт новый. Реальная проверка пары WAV — полного и обрезанного — подтверждает прохождение через FFmpeg и Whisper. В спорном случае слушатель может принять дубль. |
| **C1.5. Экспорт и сквозная приёмка**. После C1.3–C1.4 | WAV/MP3, паузы, режимы черновика и выпуска, история скачиваний, восстановление UI после перезагрузки. | Для трёх выбранных дублей проверить порядок PCM и точное число кадров WAV, декодировать MP3, сверить снимок. Изменение паузы или формата не вызывает Vox/Whisper. Сбой кодера и повреждение исходного WAV дают понятную ошибку. Пройти браузером весь путь от вставки до скачивания, включая замену одного дубля, только клавиатурой и при узком окне. |

**Что осталось проверить на звуке.** Блокирующих архитектурных вопросов нет. До завершения C1 нужны короткие русскоязычные образцы для трёх решений: подходят ли границы в 240 знаков и пауза 150 мс для естественной речи, насколько стабилен тембр после закрепления Design-пробы, как часто Whisper ошибается на именах, числах и однословных репликах. Проверять на одинаковых текстах с несколькими дублями, сохраняя мнение слушателя отдельно от машинной оценки. Границы, пауза и пороги имеют стартовые значения, поэтому это не препятствует началу C1.

## 7. Проверка выводов C0A

Коммит получен по полному SHA в отдельную временную копию. Проверены импорты, места вызовов, сериализация запросов, условия допуска дубля и публикация файлов. В этой копии под Python 3.11 с `PYTHONPATH=src` выполнены исходные тесты:

```text
python -m pytest -p no:cacheprovider -o addopts= -q tests/test_speech.py tests/test_voxcpm_adapter.py tests/test_lab.py
72 passed
```

В выборку входят восстановление после отмены, сохранение выбора при новой попытке, обновление плана, повторная оценка без мутации дубля, отдельный составной дубль и изменение пауз без синтеза. Тесты адаптера подменяют модель и проверяют фактические аргументы вызова, Lab проверяет обработку ошибок и запоздалых событий. Это проверка логики данного снимка. Прослушивание на реальных весах, измерение задержки и браузерная приёмка относятся к C1. [Production-тесты][ts] · [тесты Lab][tl] · [проверки вызова Vox][tv]
