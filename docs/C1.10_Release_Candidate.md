23 ноября 2026 года. База выпуска — `main` после C1.9C (`a8c85ac`). Пакет нацелен на RHEL 9 x86_64 с локальным NVIDIA GPU.

## Аудит переноса

- Windows-команда `cmd.exe` и OpenSSH используются только для прежнего режима с `TTS_CLIPS_VOX_SSH`. Служба Linux запускает воркер прямым вызовом Python с локальными весами. Вызовы FFmpeg и Whisper используют список аргументов, Windows-флаги запуска имеют безопасное значение по умолчанию на Linux. VoxCPM2 явно требует доступный CUDA GPU.
- Исходники и собранный интерфейс находятся в `/usr/share/tts-clips`. Служба `tts-clips` пишет SQLite, WAV и экспорт в отдельный каталог. SIGTERM завершает очереди, после запуска используются существующие правила возобновления. Один экземпляр Uvicorn обслуживает все браузеры.
- API и фронтенд работают с одного origin. NGINX завершает TLS и проверяет учётные данные. Действующая корпоративная аутентификация может выполнять ту же роль. При обновлении веб-стека учтено исправление Starlette для обработки `Range`, которое важно для файлового API. [Бюллетень Starlette](https://github.com/Kludex/starlette/security/advisories/GHSA-7f5h-v6xp-fcq8)
- Сохранены подготовка и разбиение C1.9C, Voice Design/Clone, варианты и выбор дублей, отчёты полноты и точности, восстановление, допуски и история экспорта. Схема базы C1.9C используется при миграции с Windows.

Окончательная приёмка требует сервера RHEL 9 с NVIDIA. На нём ещё нужно выполнить `tts-clips-setup` целиком, получить новый дубль локальным CUDA-воркером, проверить корпоративный адрес с SELinux Enforcing и убедиться, что обе службы стартуют после перезагрузки физического сервера. Порядок проверки приведён в [инструкции администратора](Server.md#приёмка-на-сервере).
