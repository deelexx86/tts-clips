# C1.11 · Развёртывание TTS Clips на двух Docker-хостах

На первом сервере NGINX отдаёт React по HTTP на порту 80 и пересылает `/api/*` на внутренний HTTP-адрес второго сервера. Корпоративный шлюз обеспечивает внешний HTTPS и проверяет доступ пользователей. На GPU-сервере один процесс FastAPI обслуживает порт 8765, запускает локальный VoxCPM2 на NVIDIA и Whisper на CPU и хранит очереди, SQLite и аудио на диске хоста. FFmpeg собирает WAV и MP3. Два Compose-проекта связываются через IP или DNS корпоративной сети.

## GPU-сервер

1. Подготовьте Linux x86_64, Docker Engine с актуальным Compose v2, NVIDIA GPU с драйвером для CUDA 12.8 и NVIDIA Container Toolkit. После установки Toolkit выполните `sudo nvidia-ctk runtime configure --runtime=docker`, затем перезапустите Docker в окно обслуживания. В образе уже есть CUDA-библиотеки PyTorch. [Инструкция NVIDIA для RHEL и Docker](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/install-guide.html)
2. Ограничьте на корпоративном сетевом экране входящий TCP 8765 внутренним исходящим IP frontend-сервера. Если ограничиваете на Docker-хосте, фильтруйте перенаправляемый трафик до принимающих правил Docker, например в `DOCKER-USER` для iptables. Проверьте доступ с frontend и его отсутствие с другого узла. [Опубликованные порты и firewall Docker](https://docs.docker.com/engine/network/packet-filtering-firewalls/)
3. Подготовьте каталоги для UID:GID `10001:10001` и скопируйте `.env.example` в `.env`. Задайте `TTS_CLIPS_BACKEND_BIND` внутренним IPv4-адресом GPU-сервера. Значение по умолчанию `127.0.0.1` доступно только локально.

   ```bash
   sudo install -d -m 0755 /srv/tts-clips
   sudo install -d -o 10001 -g 10001 -m 0750 /srv/tts-clips/{models,data,cache}
   cp .env.example .env
   docker compose -f compose.backend.yaml up -d
   docker compose -f compose.backend.yaml logs -f backend
   ```

   Compose монтирует каталоги с приватной SELinux-меткой `Z`. Используйте отдельные каталоги для этого контейнера. При использовании user namespace remapping назначьте на хосте соответствующий отображённый UID/GID. Запускайте один backend на набор данных. [Параметры bind mount в Compose](https://docs.docker.com/reference/compose-file/services/#volumes)

| Хост | Контейнер | Содержимое |
| --- | --- | --- |
| `/srv/tts-clips/models` | `/models` | Снимки моделей и файлы незавершённых загрузок |
| `/srv/tts-clips/data` | `/data` | `clips.sqlite3`, `clips.audio`, `clips.exports` |
| `/srv/tts-clips/cache` | `/cache` | Кэши библиотек и временные файлы |

При первом запуске backend скачивает отсутствующие файлы с Hugging Face в каталоги `*.partial`. Сохраняйте их для продолжения загрузки. Готовые снимки публикуются после проверки всех SHA-256. На следующих запусках хеши проверяются локально. При ошибке журнал показывает путь к проблемному файлу. Для ремонта остановите backend, переместите повреждённый снимок в отдельный каталог и восстановите его из проверенной копии либо запустите загрузку заново.

Если корпоративный прокси подменяет TLS-сертификаты исходящих соединений, передайте контейнеру доверенный CA bundle через локальный Compose override и укажите его путь в `REQUESTS_CA_BUNDLE`. Для закрытого контура используйте предварительное копирование ниже.

### Установка без доступа в интернет

На подключённом узле соберите backend-образ, перенесите его через корпоративный registry или `docker save` / `docker load`. Скопируйте файлы из `packaging/models.json` со строго указанными ревизиями в каталоги `<имя>-<полный hash ревизии>` под `/srv/tts-clips/models`. Можно перенести целиком снимки из C1.10 или с уже настроенного backend. У файлов должны быть права чтения для UID 10001, у каталогов — права чтения и записи для этого UID. При первом запуске backend создаст недостающую квитанцию только после проверки всех хешей. Задайте `HF_HUB_OFFLINE=1` в `.env` и выполните команду запуска. При отсутствии сети для загрузки образов используйте `up -d --no-build --pull never`.

## Frontend-сервер

Скопируйте `.env.example` в `.env` и задайте `TTS_CLIPS_BACKEND_URL=http://<внутреннее-DNS-имя-или-IPv4>:8765`. Направьте корпоративный шлюз на HTTP-порт 80 frontend-сервера и ограничьте доступ к порту адресами шлюза.

```bash
docker compose -f compose.frontend.yaml up -d
curl -f http://127.0.0.1/api/clips
```

При изменении адреса отредактируйте `.env` и повторите `up -d`. Compose пересоздаст контейнер с новым адресом из того же образа. Если upstream недоступен, NGINX отдаёт API-ответ 503, а браузер показывает сообщение об ошибке рабочей области.

## Обновление и диагностика

- Соберите соответствующий образ командой `docker compose -f compose.frontend.yaml build` или `docker compose -f compose.backend.yaml build`, либо доставьте готовый образ с такими же тегами. Затем повторите `up -d` соответствующего проекта. Образы ставят зависимости при сборке. Снимки прежних ревизий и данные остаются в каталогах хоста.
- Перед обновлением backend остановите его через `docker compose -f compose.backend.yaml stop` и снимите резервную копию всего каталога `data`. Сохраняйте SQLite и каталоги аудио одним набором. После запуска проверьте клип, выбранный дубль и скачивание экспорта.
- `docker compose -f compose.backend.yaml ps` и `logs --tail 100 backend` показывают состояние и подготовку моделей. При отказе GPU проверьте `nvidia-smi` на хосте и `docker compose -f compose.backend.yaml exec backend python -c 'import torch; print(torch.cuda.is_available())'`. Для ошибок прокси проверьте `logs --tail 100 frontend`, DNS и `curl -f http://<GPU-сервер>:8765/api/clips` с frontend-хоста.
- В обоих проектах задан `restart: unless-stopped`. Backend получает до 120 секунд для остановки приложения и фоновых задач. Для незавершённых дублей действует обычное восстановление очереди TTS Clips.

## Результаты проверок

| Проверка | Результат |
| --- | --- |
| Сборка | Собраны оба образа. Для backend использован собранный этап зависимостей с закреплёнными версиями и проверкой SHA-256. Крупные колёса взяты из локального кэша. Чистую загрузку всех колёс с публичных источников остановили из-за скорости сети. В backend проверены UID:GID 10001:10001, пустой `/models` в образе, импорты PyTorch 2.10.0+cu128, torchaudio и VoxCPM. |
| HTTP и браузер | Два Compose-проекта в отдельных bridge-сетях Docker Desktop на одном физическом хосте. Chrome открыл React на порту 80. При недоступном upstream API вернул 503, интерфейс показал ошибку и кнопку повтора. Смена адреса на опубликованный порт backend сохранила ID frontend-образа. Через NGINX прошли запросы чтения и записи, скачивание и HTTP Range. |
| Модели | С пустого каталога backend загрузил `config.json` и инициировал запрос весов. Полную холодную загрузку всех весов не дожидались. В отдельном тесте backend продолжил загрузку настоящего `tokenizer.json` с 65 536 байт, сверил SHA-256 и опубликовал снимок. С готовыми файлами и `HF_HUB_OFFLINE=1` создал недостающую квитанцию, при пересоздании повторно использовал снимки. Повреждённый `config.json` остановил подготовку с указанием пути и SHA-256. |
| Данные и звук | На перенесённом WAV выполнен реальный Whisper QC и собран новый WAV/MP3 командой через прокси. Backend использовал FFmpeg 5.1.9. После штатной остановки и пересоздания сохранились клип, завершённое задание, выбранный дубль, отчёт QC и SHA-256 скачанных файлов. |
| Регрессии | 66 тестов Python, 3 теста интерфейса, сборка Vite, проверка обеих конфигураций Compose и сборка RPM прошли. |

На стенде GPU-резервирование сняли только в тестовом override. Локальный процесс VoxCPM2 запустился и вернул диагностику отсутствия NVIDIA. Приёмка на двух физических серверах, работа с SELinux Enforcing и реальный синтез через CUDA внутри Docker остаются непроверенными.
